# 前置 VTOYEFI 无损安装

## 设计边界

用户先用分区软件在磁盘前部留出未分配空间。本功能只在这块空间写入 Ventoy，保持原数据分区的起点、大小和文件系统内容；不负责移动或缩小原数据分区。原数据分区由第 1 项移为第 2 项，其他表项只在插入所需范围内后移。GPT 原有分区 GUID 保留，分区编号可能变化。

仅接受 512 字节逻辑扇区的基本 MBR/GPT 磁盘（包括 512e，不包括 4Kn）。GPT 限定 128 个 128 字节表项、主表在 LBA 2、备份表在磁盘末尾，要求主备表有效且一致。拒绝扩展/逻辑分区、LDM、Storage Spaces、重叠分区和没有空分区表项的布局。Windows 保留系统盘禁止安装和数据盘符检查。

固定布局（LBA 以 512 字节为单位）：

| 范围 | 用途 |
| --- | --- |
| LBA 0–2047 | 分区元数据及 BIOS 引导区域 |
| LBA 2048–67583 | 第 1 分区 VTOYEFI，32 MiB |
| LBA 67584 至原数据分区起点 | 保持未分配；允许有间隙 |
| 原数据分区的原位置 | 第 2 分区，起点至少 67584，即 33 MiB |

建议用户预留 64 MiB，程序只使用前 33 MiB，其余间隙不处理。文件系统内的可用空间不等同于分区前的未分配空间。手工移动原分区本身的风险不由本功能消除。

新布局保留现有 EFI 镜像大小及 GPT 类型/属性策略。旧标准布局继续使用原安装、升级入口。前置布局按数据/EFI 角色定位，数据实际起点通过现有启动参数和 sysfs 取得，不固定成 33 MiB。

## 使用入口

以下命令仅用于已完整重建、包含有效 `ventoy/front-efi.sha256` 的安装包。仓库现有预编译文件不代表已经支持本改动。

Windows 图形界面：配置选项 → 无损安装（EFI 前置）。

确认窗口显示目标物理磁盘、型号、容量、盘符、分区类型以及数据分区起点，并默认选择取消。操作期间禁用刷新、设备切换和菜单；后台使用独立磁盘信息副本。空间不足时直接显示首个分区起点和所需空间，其他预检失败分别提示具体原因及处理方法。

Windows CLI（将 N 替换为核实后的物理磁盘编号）：

```text
Ventoy2Disk.exe VTOYCLI /I /FrontEfi /NoSB /PhyDrive:N
Ventoy2Disk.exe VTOYCLI /U /NoSB /PhyDrive:N
```

`/FrontEfi` 隐含无损安装，仅可用于 `/I`。升级自动识别前置布局。安装器与备份必须位于另一块物理磁盘。前置路径不启用 Secure Boot，启动时须关闭固件 Secure Boot。

Windows CLI 拒绝未知或拼错的参数、重复/冲突操作、多个目标和无效磁盘编号；`/FrontEfi` 与 `/GPT`、`/R:`、`/FS:` 不能合用。拼错前置选项不会转入普通格式化安装。命令行仍用于无人值守调用，不增加交互确认；执行前需核对目标编号。

Linux CLI（将 sdX 替换为核实后的整盘设备）：

```sh
sudo sh Ventoy2Disk.sh -i --front-efi /dev/sdX
sudo sh Ventoy2Disk.sh -u /dev/sdX
```

`--front-efi` 不与 `-r` 或 `-g` 合用，保留原磁盘分区类型；已有 Ventoy 不重复执行无损安装。数据分区须先卸载，不能用作活动 swap、RAID 或设备映射器成员。安装包及工作目录应放在其他磁盘。

Linux 安装和升级均在确认前显示目标型号、容量、分区起点及恢复目录。需准备约 66 MiB 的内存和工作空间，工作盘建议至少留出 80 MiB；空间和内存不足会在首次写盘前停止。临时挂载点卸载失败时停止，只允许删除已卸载的空目录，不递归清理其中内容。

LinuxGUI 可以识别新布局，但前置布局升级明确转交 CLI，防止进入旧 GUI 写入流程。Plugson 按实际数据分区定位配置文件。

## 写入及恢复

安装前核对前部空闲区、分区表、扇区大小和安装包 SHA256。先保存备份并完整准备启动镜像，再写 EFI 内容、引导内容，最后提交新分区表；写入后回读比对。GPT 同时维护主备分区表与 CRC。升级保留磁盘 UUID 和 LBA 2040–2047 的配置区域，该配置区域也随引导内容回读验证。Windows 对启动文件短读、解压失败、长度不符和 EFI 文件替换失败立即停止，不将损坏的内存镜像当成有效源写盘。

Windows 将备份保留为安装目录下 `ventoy/front-efi-diskN-PID-TICK.bin`：

- 前 33 MiB 原始内容；
- GPT 额外拼接磁盘最后 33 个扇区；MBR 无此尾部。

Windows 核对备份目录实际所在物理磁盘和可用空间，界面及日志显示完整备份路径（可能采用卷 GUID 路径）。同次调用失败且句柄仍有效时尝试恢复上述区域，并对恢复内容全量回读验证；备份始终保留。结果明确区分“尚未写盘”“已恢复且验证通过”“恢复未能确认”。写入受阻时直接失败，不进入删除 EFI 分区、修改分区类型或清盘重试。

Linux 在当前安装目录创建 `ventoy-front-backup.*`，包含 `snapshot.bin`、`disk.txt`、`front-33MiB.bin`、`tail-33sectors.bin` 和准备好的启动镜像。只有 `backup.ready` 存在时，才表示事务已完成备份写入及同步；失败后保留文件，不自动回滚。

Linux 写入集中在 `vtoycli partresize -W`：一次以 `O_EXCL` 打开磁盘，核对确认前快照，完成备份并再次核对后才写入；使用同一磁盘句柄完成写入和回读。回读使用内存缓冲区，首次写盘后不再创建大临时文件。内部返回值 `1` 表示未写盘，`3` 表示已尝试写入、需检查恢复；异常中断提示磁盘可能已写。`disk.txt` 记录容量、设备号、可用的内核 diskseq 以及备份 CRC32。旧内核没有 diskseq 时，仍核对设备号、容量和完整分区快照，但无法仅据此区分使用相同设备号且内容完全相同的克隆磁盘。

安装、升级期间都应关闭其他分区工具，避免并发修改。Windows 锁定磁盘句柄后核对设备属性及完整分区表；Linux 在首次写盘前再次核对身份和分区快照。

断电情况下不保证自动恢复。恢复前必须核对原磁盘、容量和备份来源，不能通过重新执行普通格式化安装代替恢复。

## 构建与防止混用旧产物

前置安装及升级要求安装包根目录下的 `ventoy/front-efi.sha256` 严格列出以下三个文件：

1. `boot/boot.img`
2. `boot/core.img.xz`
3. `ventoy/ventoy.disk.img.xz`

清单由完整打包流程生成。不要手工生成清单以跳过构建校验；只修改安装器 EXE 或 Shell 脚本无法得到可启动的新布局。

在项目原有 Linux 构建环境中，从 INSTALL 目录运行：

```sh
sh all_in_one.sh FRONT_EFI
```

打包校验 GRUB 构建回执及关键组件中的 `VTOY_FRONT_EFI_V1` 能力标记，缺失则拒绝前置包。Windows 安装器和四架构 `vtoycli` 还必须包含本轮异常处理的 `VTOY_FRONT_EFI_SAFE_V2` 标记；Linux 脚本运行前查询工具协议版本，拒绝旧 helper 与新脚本混用。普通包可保留旧组件，但不生成前置清单。GRUB 回执绑定实际 BIOS/EFI 启动二进制；BIOS core 内部压缩，不能只在压缩文件中搜索字符串判断版本。

必须重建受影响的 Windows 安装器、PE `vtoyjump`、GRUB、Ventoy EFI、VtoyTool、vtoycli、LinuxGUI/Plugson，并重新打包 cpio 和 EFI 分区镜像。原签名流程保留；本次不提供已受信任的 Secure Boot 签名。

VtoyTool `01/02` 为旧兼容工具链的产物，仓库没有提供对应构建说明，须在相应环境重建。不能把 `00` 复制过去冒充兼容版本。各 Unix 平台的预编译模块也不能因源码修改而视为已验证。
